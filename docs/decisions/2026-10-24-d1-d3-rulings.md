## 裁决

- Setup: Ruling: 不建 git worktree，改用同名特性分支原地工作 — Windows + 中文路径下多一份工作副本的同步成本高于收益，且 main 本身不会被触碰 — 成本：若后续需要并行跑两个计划，需再补 worktree。
| Task 4 → Task 5–9 | `build_writer_context` 输出含 `gate_findings`，但 Task 4 定义的 `RunState` 没有 `gate` 字段（守门人在 D4） | **冲突**。Ruling: `RunState` 增加 `gate: Any | None = None`（D4 时收窄为 `GateResult`），writer builder 从 `state["gate"].findings` 取，缺省 `[]` — 成本：D4 改一处类型注解 |
| Task 9 → Task 10 | Task 9 的 CLI `meta.failed_checks` 需要 `decisions.evaluate()`，而 `decisions.py` 在 Task 10 才落地 | **冲突**。Ruling: Task 9 的 `meta` 只输出 `status/rounds_used/best_round/usage`，`failed_checks` 由 Task 10 补进 CLI — 成本：Task 10 多改 `cli.py` 一处 |
- Task 1: Ruling: 模型名 `deepseek-chat` 已下线，改用 `deepseek-flash`（定价页 2026-10-24，含 JSON Output 支持）— 计划里的测试字面量随之改 — 成本：若后续换 model 名，需同步 PRICES 与 .env.example
- Task 1: Ruling: PRICES 单位改为「美元/百万 token + 取高峰价」，不是计划写的「元」— 厂商以美元计价且分峰谷，直接折元会把汇率和时段藏进常量里 — 成本：Task 2 算 cost_cny 时要显式乘汇率（届时补 `usd_cny_rate`）
- Task 1: Ruling: 增加 `WriterNotConfigured` — 计划只要求 ReaderNotConfigured，但 writer 缺 key 同样是配置错误，不该等第一次调用才炸 — 成本：多一个异常类
- Task 2: Ruling: openai 3.37 的传输层是 `httpx2`（不是 httpx），测试 `import httpx2 as httpx`，httpx2 进 dev 依赖 — 环境里没有 httpx 包 — 成本：若回退到 openai 2.x 需改 import
- Task 2: Ruling: 不引入 tenacity，传输层失败与 schema 失败共用「两次调用」预算 — 一个预算比两套重试更好解释，也少一个依赖 — 成本：将来若要指数退避需自己加
- Task 2: Ruling: PRICES 是美元/百万 token，cost_cny = usd × `usd_cny_rate`(7.1)；未登记价格抛 `UnknownModelPrice` — 宁可报错，也不按 0 计费把成本数字做成假的 — 成本：读者模型（Qwen/GLM）的价格必须补进 PRICES 才能跑 live
- Task 2: Ruling: 默认 `thinking: disabled` — DeepSeek 默认开思考模式，会忽略 temperature 并推高时延（§3 G1 要 3 分钟内出稿）— 成本：写作质量若不足可经 THINKING_ENABLED=1 打开
- Task 2: Ruling: schema 失败测试用不可强转的值 `"abc"`，而非 `"0.8"` — pydantic 默认 lax 会把数字字符串强转，那是想要的宽容；垃圾值才是要拒的 — 成本：类型漂移（"0.8"）不会被判为失败，靠 ge/le 范围兜底
- Task 2: Ruling: `except (APITimeoutError, APIConnectionError)` 简化为 `except APIConnectionError` — APITimeoutError 是其子类，mutation 测试证明原写法冗余
- Task 3: Ruling: `Usage` 保持 dataclass（不是 pydantic），并从 `app/llm/client.py` 移到 `app/schemas.py` — 它是内部累加器、从不来自模型输出，dataclass 支持计划里的位置参数构造 — 成本：若将来要序列化进 API 响应，需手动 asdict
- Task 3: Ruling: 计划的 `Usage.merge` 断言用浮点字面相等（`0.1 + 0.2 != 0.3`），改为 `pytest.approx` — 这是测试本身的缺陷，不是实现缺陷 — 成本：无
- Task 4: Ruling: `reading_scene` 作为 `RunState` 的可选键存在（不是 PersonaInput 字段）— §6 要求读者知道「刷手机场景」，但画像 schema 没这个字段，硬编码常量等于让模型自己编场景 — 成本：调用方要给就显式传
- Task 5: Ruling: `anchors` 不合规时用「过滤」而非计划里的「重问一次」— anchors 只是 §8 保真校验的输入，缺了不会产出错稿，重问要多花一次调用 — 成本：若模型持续编锚点，可用锚点会变少
- Task 5: Ruling: 节点内部把 usage 并入 state（`state.merge_usage`），从而保持计划签名 `run_profile(state, deps) -> ProfileCard` 不变 — 成本：节点对 state 有写副作用，需在 docstring 里写明
- Task 5: Ruling: 测试夹具放 `tests/helpers.py` 而非 conftest — 避免模块间隐式共享夹具 — 成本：无
- Task 7: Ruling: 计划的 `test_body_uses_at_least_two_real_material_items` 只断言了假模型返回的正文，等于测夹具；改成由**节点强制**（原料不足 2 条就带错误重出一次），并补正向用例 `test_underused_material_triggers_one_retry` — 成本：素材不足时多一次调用
- Task 7: Ruling: 第一轮模型若仍返回 `responses`，直接丢弃而非抛错 — 那是模型的越界输出，不是契约破坏（§7 只要求「第一轮为空」的结果）— 成本：无
- Task 8: Ruling: 读者把判定卡 append 进 `state["verdicts"]`（降级时 append 同一个对象）— 降级重复会自然触发一级卡死，正好落实「降级不烧钱」— 成本：loop 不能再重复 append
- Task 8: Ruling: 放弃雏形的 `{context_json}` 占位 + replace 注入，改为 system=指令、user=JSON — 正文里的花括号曾把雏形坑过一次（它自己的报告里提到修过），分离后没有占位符可冲突
- Task 9: Ruling: 提前落地 `decisions.passed()`（原计划在 Task 10）— CLI 必须输出 status，而把通过条件复制一份就是两套真相源，也违反 §7「硬编码、单一」— 成本：Task 10 变成「补齐」而非「新建」
- Task 9: Ruling: `FakeLLM` 增加 schema 类型断言 — 夹具错配时应报「排到 X 与 Y 不符」，而不是在下游冒 AttributeError
- Task 10: Ruling: `angle_history` 在重开时记录「旧角度 + 新角度」两条，`len>=2` 即锁死重开 — 计划要求「最多重开 1 次」且测试断言长度 2 — 成本：history 里含当前角度，语义上是「已产出的角度」而非「已废弃的角度」
- Final: Ruling: I9 未修（角度重开没有强制「上一版错在哪」）— 修它要动 `Angle` schema 与 planner 上下文，紧邻 D4 的策划改动 — 成本：重开理由不可审计，§7「不接受无理由换向」暂时只靠 `why_not_others` 间接覆盖
- Final: minor (deferred): M2 类型强转策略无测试固定；M3 `run_once` 与 `run_loop` 重复；M4 sentence_index 不校验句子数；M5 读者 prompt 重复携带正文；M6 `reading_scene` 无调用方；M7 失败路径的 CLI 输出缺测试；M8 passed 时 best_round=None 与 §5 样例不一致；M9 正文 prompt 注入未加固；M10 `.superpowers/` 不入库导致 rulings 不可从 clone 复现
