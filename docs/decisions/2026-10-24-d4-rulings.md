## 裁决

- **`run_loop` 与 `finish_draft` 拆分**：`run_loop` 只负责讨论循环，定稿尾部（封面→人味校订→守门人）单独成 `finish_draft`，由 CLI 串起来。理由：原计划把尾部塞进 `run_loop`，会破坏 D1–D3 那批「只测循环」的用例（9 个挂掉）。拆开后 D5 换 LangGraph 时，尾部正好是一组独立节点。
- **规则库用结构化字段而不是 spec 里的 `rule: "300 <= len(body) <= 800"` 字符串**：字符串要自己写解析器，`min/max` 字段直接可校验、可扩。代价：与 §9 的示例 YAML 形状不同，语义一致。
- **守门人把「模型返回空 findings」按「未判误报」处理**，即保守失败：宁可 gate_blocked，也不放行。这是联调时暴露的——模型偶尔返回空数组。
- **人味校订在「零命中」时跳过模型调用**（联调发现）：原文 AI 味分为 0 时，模型仍被要求改写，结果改出超长/丢数字的稿子被保真拦下，白烧一次调用还留下 5 条「被拦下的改动」。现在零命中直接 `fidelity="skipped"`，有守门人 hints 时仍会改写。
- **测试文件命名**：D4 链路用例放 `tests/test_pipeline_d4.py`，没有像计划那样追加进 `test_loop.py`；`test_loop.py` 保持「只管循环」的职责。
- **报告样本入库**：`docs/samples/report-p01.html` 是一次真实运行（status=passed，0.0368 元，34.7 秒）导出的单文件 HTML，用于说明「面试官点不开 demo 时给他什么」。
- **`app/report/html.py` 豁免 E501**：内联 CSS 拆行只会更难读。
